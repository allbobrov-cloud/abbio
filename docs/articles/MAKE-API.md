# Статьи ABBiO: контракт для Make

Для сохранённой цепочки владельцем согласован отдельный совместимый `POST /api/blog/articles`: multipart HTML + base64-обложка, сохранение и публикация одним запросом. Настроен только HTTP 19; точные поля, переменная и проверки — [MAKE-MODULE19.md](MAKE-MODULE19.md). Основной JSON API ниже сохраняет прежний draft/publish-контракт.

Контракт первой версии. Маршруты появятся на боевом домене после отдельной публикации сайта. Статьи, редакции и оптимизированные изображения хранятся в PostgreSQL, в отдельной схеме `abbio_editorial`. Существующие таблицы приложения не используются.

## Сервер

Задать серверные `DATABASE_URL` и `ARTICLES_API_TOKEN`. Токен — случайная строка не короче 32 символов. Не использовать `NEXT_PUBLIC_*`, не записывать значения в Git или журналы сценария. Строка БД может содержать параметры TLS, предоставленные хостингом; проверку сертификата не отключать.

До запуска раздела выполнить `npm run articles:migrate` из окружения с доступом к БД. Миграция транзакционная, повторяемая, создаёт только схему `abbio_editorial`. Сборка сайта не запускает миграции. Сетевой адрес БД, предоставленный владельцем, предположительно внутренний: проверять подключение из сети хостинга. Для локальных тестов используется отдельная БД, а не production.

Драйвер `pg` использует пул максимум из пяти подключений на процесс, с таймаутами. При нескольких экземплярах приложения учитывать суммарный лимит. Резервное копирование PostgreSQL должно включать схему `abbio_editorial` — в ней находятся также файлы изображений. Периодичность и проверку восстановления настроить на хостинге. Бинарные обложки в БД упрощают первый запуск; при существенном росте медиатеки их можно перенести в object storage через тот же asset-интерфейс.

## Общие заголовки

Все API ниже приватные:

```http
Authorization: Bearer <ARTICLES_API_TOKEN>
Content-Type: application/json
Idempotency-Key: <unique-operation-id>
```

`Idempotency-Key` обязателен для всех изменений: 8–128 символов, латинские буквы, цифры, `-`, `_`, `:`. Сохраняйте один ключ при повторе той же операции после таймаута. Для нового изменения создавайте новый ключ. Повтор той же операции вернёт сохранённый результат; тот же ключ с другими данными — `409 idempotency_conflict`. GET не требует этого заголовка. Рекомендуется последовательно обновлять одну статью в Make.

## 1. Загрузить изображение

`POST /api/articles/assets`. Тело — **бинарный файл, не JSON и не multipart**. В HTTP-модуле Make передать данные скачанного файла как тело запроса. `Content-Type: image/jpeg` (или реальный формат); Authorization и Idempotency-Key остаются.

JPEG, PNG, WebP, AVIF; до 5 MiB и 16 миллионов пикселей. SVG, анимации и неизвестные форматы отклоняются. Сервер удаляет метаданные, исправляет ориентацию, ограничивает размер 1920×1920 без увеличения и сохраняет WebP. Ответ `201`:

```json
{
  "id": "<asset-uuid>",
  "url": "/media/articles/<asset-uuid>.webp",
  "width": 1600,
  "height": 1000,
  "contentType": "image/webp",
  "bytes": 120000
}
```

Значения выше иллюстрируют структуру ответа. Используйте фактический `url` в `coverImage`, `ogImage` и Markdown. Произвольные внешние URL изображений не принимаются. Файлы доступны по их URL, в том числе до публикации статьи; загрузка не предназначена для конфиденциальных материалов. Alt задаётся в статье, а не в бинарном запросе.

## 2. Создать черновик

`POST /api/articles`, JSON; ответ `201` с `id`, `revision`, `status` и данными статьи.

```json
{
  "slug": "kak-proverit-put-do-zayavki",
  "status": "draft",
  "title": "Как проверить путь до заявки",
  "description": "Вводный абзац для страницы статьи.",
  "excerpt": "Короткое описание для карточки.",
  "category": "websites",
  "tags": ["UX", "Конверсия"],
  "author": "ABBiO",
  "coverImage": "/media/articles/<asset-uuid>.webp",
  "coverAlt": "Содержательное описание обложки",
  "content": "## Что проверить\n\nТекст материала.\n\n## Что делать дальше\n\nСледующий шаг.",
  "featured": false,
  "relatedServices": ["websites"],
  "relatedCases": ["bogov"],
  "relatedArticles": []
}
```

Это пример, не готовая статья: подставить настоящий UUID загруженного файла. Категории: `websites`, `marketing`, `seo`, `analytics`, `practice`. Tags — до 12 уникальных строк. Связанные статьи указываются существующими slug, до 10 ссылок каждого типа. Услуги и кейсы проверяются по текущим данным сайта.

`title`, `description`, `excerpt`, `category`, `content`, `slug` обязательны при создании. Обложку можно добавить позже в draft, но для публикации она и alt обязательны. Опциональные SEO-поля: `seoTitle`, `seoDescription`, `ogTitle`, `ogDescription`, `ogImage`; `null` означает использовать основной текст/обложку. Автор по умолчанию ABBiO; допускаются только подтверждённые имена из текущей команды. `readingTime`, `id`, даты обновления и canonical рассчитывает сервер — их передавать не нужно. Slug: 3–120 символов, строчные латинские буквы/цифры и одиночные дефисы; после создания менять его через PATCH нельзя. Существующий slug → `409 slug_conflict`, не обновление чужой статьи.

## 3. Обновить рабочую редакцию

`PATCH /api/articles/<id>`, JSON, новый Idempotency-Key:

```json
{ "expectedRevision": 1, "title": "Уточнённый заголовок", "content": "## Новый раздел\n\nОбновлённый текст." }
```

Передавать только изменяемые поля. Ответ возвращает увеличенный `revision`. `GET /api/articles/<id>` позволяет прочитать рабочую редакцию. Обновление опубликованной статьи **не меняет публичную редакцию**; для этого нужна команда publish. При конфликте версии `409 revision_conflict`: получить актуальную запись и решить, какие изменения применить, не повторять перезапись вслепую.

`revision` — последняя рабочая редакция, `publishedRevision` — номер опубликованной редакции или `null`. `status: published` означает, что статья видна читателям; если номера редакций различаются, API возвращает более новую рабочую версию. После publish номера совпадают. Не передавать эти серверные поля обратно в CREATE/PATCH целиком.

## 4. Опубликовать

`POST /api/articles/<id>/publish`:

```json
{ "expectedRevision": 2 }
```

В этот момент сервер повторно проверяет content, обложку/alt, изображения и связи. Редакция становится доступной по `/articles/<slug>`, появляется в каталоге, рекомендациях и sitemap, без новой сборки сайта.

При первой публикации можно передать `publishedAt` в ISO 8601 с часовым поясом. Дата не должна быть в будущем. При последующем редактировании первоначальная дата сохраняется. Для публикации новой редакции повторно вызвать publish с её revision. Запланированная публикация — задача расписания Make, статуса scheduled пока нет.

## 5. Снять публикацию

`POST /api/articles/<id>/unpublish`, тело `{ "expectedRevision": 2 }`. Статья становится draft: публичный URL возвращает 404, список и sitemap её не содержат. История редакций и дата первой публикации сохраняются.

## Markdown

Поддержаны H2/H3 (`##`/`###`), абзацы, выделения, списки, цитаты, таблицы GFM, код, разделители и ссылки HTTPS/локальные ссылки. H1 задаётся шаблоном. Сырой HTML, MDX и опасные URL отклоняются. Оглавление появляется при двух и более H2; якоря назначаются автоматически. Картинки — только загруженные assets, с alt:

```markdown
![Описание изображения](/media/articles/<asset-uuid>.webp "Подпись под изображением")

:::callout{tone="tip" title="Что проверить"}
Текст примечания. Допустимые tone: note, tip, warning.
:::

::cta
```

`::cta` вставляет фиксированный блок «Есть похожая задача?» и открывает существующую форму. Вставлять его по редакционному решению, не автоматически после каждого абзаца. Другие директивы и произвольные атрибуты запрещены.

## Ошибки и проверки сценария Make

Формат ошибки: `{ "error": { "code": "revision_conflict" } }`. Статусы: 401 — авторизация; 400 — JSON/ключ идемпотентности; 404 — запись; 409 — конфликт; 413 — размер; 415 — Content-Type; 422 — валидация; 503 — конфигурация/БД недоступны. Успешный повтор не создаёт новую редакцию. Для 503 и сетевых таймаутов — повтор с тем же ключом и задержкой; для 4xx — исправить входные данные/условия.

API отвечает no-store и noindex/nofollow. Draft не выводится в публичных HTML, карточках или sitemap. Пустой каталог имеет noindex; после первой публикации основной `/articles` открывается для индексации. Фильтрованные страницы категорий остаются noindex, стабильный URL статьи не зависит от категории.

Одинаковый итоговый SEO-заголовок у двух опубликованных статей → `409 seo_title_conflict`. Проверяется `seoTitle`, а при его отсутствии — `title`.

Перед боевым запуском: проверить доступ приложения к БД и миграцию; загрузить реальную обложку, создать draft, убедиться в 404 и отсутствии в sitemap; опубликовать и проверить metadata/JSON-LD; обновить draft и проверить сохранение публичной редакции; опубликовать обновление. Не отправлять тестовые заявки через форму.
