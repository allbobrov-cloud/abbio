## Повторить интеграционную проверку

Использовать **отдельную пустую тестовую БД**, выполнить миграцию и запустить сайт с её `DATABASE_URL` и отдельным `ARTICLES_API_TOKEN`. В окружении скрипта задать тот же токен и `SITE_TEST_URL=http://127.0.0.1:<port>`, затем `node scripts/articles-test.mjs`. Скрипт принимает только loopback-адрес, создаёт тестовые записи, но не очищает БД. Не запускать против приложения, подключённого к боевой БД. Повторный запуск требует новой пустой тестовой БД.

## Активация на сервере

1. Задать серверные `DATABASE_URL` и `ARTICLES_API_TOKEN` из локального `.env.local`; существующие настройки формы сохранить. Не выводить секреты в логи Make.
2. Проверить доступ приложения к PostgreSQL из сети хостинга, права создания схемы, требования TLS, резервное копирование `abbio_editorial` и лимит соединений (5 на процесс).
3. При `npm start` автоматически выполняется `prestart` → `scripts/articles-migrate.mjs`: транзакционная идемпотентная миграция под advisory lock создаёт отдельную схему. Существующие таблицы приложения не меняются. При недоступной БД запуск прекращается; вручную миграцию можно выполнить через `npm run articles:migrate`. Повторный запуск проверен дважды на тестовой БД.
4. Опубликовать подготовленную версию сайта отдельным действием. Пока этого не сделано, боевой домен не содержит нового API.
5. Выполнить сценарий из `MAKE-API.md` с настоящим материалом: upload → draft → publish. Расписание публикации задаётся в Make. Настроить пять целей в существующем счётчике Метрики.

Запуск не требует ручного добавления страниц статей, правок sitemap или новой сборки для каждой публикации. Пустой каталог показывается без вымышленных материалов и закрыт от индексации.
