# Читаемые URL статей

По решению владельца 02.10.2026 ID темы Airtable не добавляется к публичному адресу. Make передаёт прежний SOURCE_ID; сценарий не меняется. Сайт хранит его отдельно в `articles.source_id` и отклоняет повторный импорт темы с новым ключом (`409 source_conflict`). Повтор с прежним Idempotency-Key возвращает ту же статью.

Новые адреса получаются из названия прежней транслитерацией. При совпадении адреса добавляется короткий номер `-2`, `-3` и т.д.; алиасы также резервируют адрес. Создание и распределение адресов защищены транзакционной advisory-блокировкой. Проверка уникальности SEO-заголовка при публикации сохранена.

Повторяемая startup-миграция убирает `-rec<14 символов>` у прежних импортов, сохраняет source_id и таблицу `article_slug_aliases`. UUID, статусы, редакции и изображения сохраняются. Старые публичные URL получают ровно HTTP301 через Next Proxy, query string сохраняется. Draft/снятые статьи остаются 404 и не раскрываются через редиректы.

Каталог, sitemap, canonical, OG и JSON-LD читают текущий slug. Старые редакционные ссылки продолжают работать через алиасы; связи рекомендаций распознают старые адреса. Сохранённые ответы идемпотентных запросов обновляются на текущий адрес. Перенос опубликованной статьи ставит в IndexNow прежний URL, новый URL и каталог в той же транзакции.

Проверено локально: повторная миграция не создаёт новых уведомлений; конфликты имён/зарезервированных URL, повторная тема, replay, HTTP301 с параметрами, canonical/sitemap и 404 draft. Тест `npx tsx --conditions=react-server scripts/articles-slugs-test.mts` запускается только с локальными DATABASE_URL, ARTICLES_API_TOKEN и SITE_TEST_URL. Дополнительно прошли 46 проверок multipart Make, eslint, TypeScript и production build. Реальные тестовые статьи в рабочую БД не загружаются.
